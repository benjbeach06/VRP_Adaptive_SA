# Time-robust tune, 2026-08-26

18h search, n=500 capacity 400, six live schedule/selection parameters (same SEARCH_SPACE as
`tools/tune.py`). Starting point (trial 0, and the normalization reference): `CHOSEN_CENTER`,
`experiment_logs/tuning/2026-08-23_chosen_center.json`.

**Different scoring from the 2026-08-23 search.** That search averaged 5 seeds at one fixed
runtime (120s). This one scores each trial across 5 DIFFERENT runtimes -- 60/120/180/240/300s,
one seed each -- so a configuration that only performs well at one point on the time schedule
cannot hide behind an average over restatements of the same runtime. Reference measured with 5
seeds per runtime instead of 1, since it is reused by every trial.

## Result

67 trials completed. **CHOSEN_CENTER (trial 0) remained the best score throughout -- nothing beat
it.** The parameters chosen from the single-runtime search hold up when scored across the whole
60-300s range; they were not overfit to one time-schedule length.

Per-runtime bests (single-seed, near the ~8-unit noise floor) each beat the reference slightly
(0.5-1.4%), but only trial 59 showed a genuine directional signature rather than scattered noise:
worse at 60s (+2.6%) and better at 120-300s (-0.5% to -1.2%) -- a real short-vs-long tradeoff the
aggregate score correctly penalized (net score 0.9996, just behind trial 0's 0.9964).

**Parameter importance** (fANOVA and PED-ANOVA, both run against the 67 trials): `plateau_reheat_exponent`
dominates (0.54-0.62 of explained variance), `max_plateau_seconds` a distant second (~0.12-0.16),
the other four parameters roughly tied and minor. Consistent with the reheat-equilibrium argument
in [planning/joint-parameter-search.md](../../planning/experiments/joint-parameter-search.md)
(`gap = C x S x R`) that the plateau quantity is the one expected to resolve cleanly.

Files: `2026-08-26_time_robust.json` (all 67 trials, params, scores, per-runtime raw objectives),
`2026-08-26_time_robust.log` (run stdout). Generated by `tools/tune_time_robust.py`.
